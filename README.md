# 電帳DIY(デモ版)

レシート・請求書・カード明細・払込用紙を「撮る・貼るだけ」で、日付・取引先・金額を自動で読み取り、
帳簿に残せる形式にファイル名を整えるツールです。

このリポジトリは**体験版(v1.0)**です。証憑データの解析処理はすべてブラウザ内で完結し、
外部サーバーに送信されることはありません(Googleドライブ連携を使う場合を除く)。

## デモの公開状況

## デモ版(v1.0)でできること — 手順

現時点でこのファイル一式(`index.html` + `lib/`)をそのまま開けば、以下がすべて実際に動きます。
体験版固有の制限(後述)はそのままですが、それ以外の主要機能はすでに使える状態です。

### 手順1. 保存先を設定する(任意)

1. 「01 保存先を設定する」を開く
2. 「フォルダを設定」を押し、任意のローカルフォルダを選択する
3. ※Chrome/Edgeで、`https://`または`http://localhost`経由で開いた場合のみ有効です。`file://`で直接開いた場合はこの機能は使えません

### 手順2. ファイルの命名ルールを決める

1. 「02 命名ルールを設定する」を開く
2. 並び順(取引年月日→取引先→金額 など)を3パターンから選ぶ
3. 「書類の種類をファイル名に含める」のチェックを必要に応じて切り替える

### 手順3. 支払いカードを登録する(カード払いがある場合)

1. 「03 支払いカードを管理する」を開く
2. 「+ カードを新規登録」から、カードの呼び方(例:楽天カード)だけを入力する(**カード番号・暗証番号・セキュリティコードは一切入力不要・保存されません**)
3. 登録したカードの「締め日」「支払日」を入力する
4. これで、このカードを使った証憑を読み込むたびに、引落予定日が自動計算されるようになる(非営業日・祝日は自動で翌営業日にずれます)

### 手順4. 証憑を読み込む

1. 「04 証憑を読み込む」を開く
2. 「カメラで撮影」「ファイルを選択」またはドラッグ&ドロップで証憑を読み込む(画像・PDF対応)
3. 自動抽出された取引年月日・取引先・金額・書類種類を確認し、必要なら修正する
4. カード払いの場合は「支払い方法」でカードを選ぶ(引落予定日が自動計算される)
5. 「これはカード明細など、複数の取引をまとめた証憑です」相当の判定は、書類種類で「明細書」を選ぶと自動的に切り替わる
6. 内容が良ければ「この内容で確定・台帳に記録する」を押す

### 手順5. 台帳を確認・出力する

1. 「05 台帳(Excel管理)」を開く
2. 処理した証憑が一覧に自動追加されていることを確認する
3. 「CSVでダウンロード」を押すと、Excelでそのまま開ける形式で書き出せる(**この機能は体験版でも無制限に利用可能**)

### 手順6. クラウド/ローカルとの同期を確認する(任意)

1. 「06 クラウド/ローカルとの同期を確認する」を開く
2. **ローカルフォルダとの比較**:手順1でフォルダを設定していれば、「ローカルフォルダと比較する」を押すだけで、台帳とフォルダの中身の差分(未保存・削除済みの可能性があるファイル)が分かる
3. **Googleドライブとの比較**(セットアップが必要、下記「Googleドライブ連携のセットアップ手順」参照)

### 手順7. 取引先の学習を確認・編集する

1. 「07 学習した取引先の表記」を開く
2. 一度読み込んだ取引先は、表記・書類種類・支払い方法が自動で記憶されていることを確認できる
3. 内容はその場で直接編集・削除できる

### Googleドライブ連携のセットアップ手順

「06」からGoogleドライブとの比較を使うには、**ご自身のGoogle CloudプロジェクトでOAuth Client IDを発行する必要があります**(開発元では発行できません)。

1. [Google Cloud Console](https://console.cloud.google.com/)で新規プロジェクトを作成する
2. 「APIとサービス」→「有効なAPIとサービス」から**Google Drive API**を有効化する
3. 「OAuth同意画面」を設定する(User Type:外部。**テストユーザーとしてご自身のGoogleアカウントを追加**すればGoogleの本審査は不要)
4. 「認証情報」→「OAuth クライアント ID」を作成する(アプリケーションの種類:ウェブアプリケーション。承認済みのJavaScript生成元にアプリの公開URLを追加)
5. 発行されたClient IDを「06」の入力欄に貼り付けて保存する

**制約:**

- 使用スコープは`drive.file`(機密性の低いスコープ、厳格な審査は不要)
- ただし`drive.file`は**このアプリ経由で開いた・作成したファイルにしかアクセスできません**。別の方法で既にドライブに置いてあるファイルは一覧に出てきません
- OAuth同意画面が「テスト」ステータスのままだと、**テストユーザーとして登録した本人(最大100人まで)しかログインできません**。第三者への配布にはGoogleの本番審査が別途必要です

### 体験版固有の制限(そのままにしています)

- 1セッションにつき10件まで(`TESTING_MODE`フラグにより現在は一時的に無制限表示)
- ファイル本体の保存(ローカルフォルダへの書き込み・ダウンロード)は無効化(台帳への記録・CSV出力は制限なし)
- 払込用紙(電気・ガス・税金等)は検出のみで、内容の自動判定は非対応

## 実装済み(デモ版でも体験可)

以下は2026年10月に追加した機能です。実際のファイル保存を除き、デモ版でも動作を確認できます。

### 事務処理規程の自動生成(04)

電子帳簿保存法の「訂正・削除の防止措置」要件は、認定タイムスタンプ・システム対応・事務処理規程の整備、の
いずれかで満たせます。個人事業主には規程の整備が最も手軽なため、屋号・管理責任者・施行日を入力すると、
国税庁の個人事業者向けひな形の一般的な構成を参考にした規程文書を自動生成し、テキストダウンロード・印刷(PDF保存)
できるようにしました。

### 勘定科目の自動サジェスト

取引先名・OCRテキストに含まれるキーワード(ガソリンスタンド、コンビニ、通信費関連サービスなど)から、
想定される勘定科目をチップ形式で候補表示します。クリックで採用、かつ取引先ごとに学習して次回以降も自動反映されます。
簡易なキーワード辞書ベースの実装です。

### インボイス登録番号チェック

OCR結果から「T」+13桁の番号を正規表現で抽出し、形式が正しいかを自動チェックして証憑に紐づけて記録します。
個人事業者の登録番号には公開のチェックディジット計算式がないため、形式(桁数)の確認にとどめています。

### 台帳の編集・削除履歴(簡易監査ログ)

台帳の各行を直接編集できるようになり、変更内容は差分(変更前→変更後)として各エントリに記録されます。
削除した場合も、削除した事実・内容は別の監査ログに残り、「🕵️ 削除履歴を見る」から確認できます。

### 過去ファイルの一括整理モード(06)

フォルダを選ぶ(または複数ファイルを選ぶ)と、**サブフォルダの中も含めて**、元のファイル名に関係なく画像・PDFをすべてOCRします。
すでにフォルダ分け済みでも「ファイル名から検索できるか」までは整っていないことが多いため、日付・取引先・金額が
ファイル名に入っているかを1件ずつ判定します。

1. **読み取り**(この段階ではファイルを変更しません)
2. **整理プランの確認**:件数、既存フォルダ、名前を変えないもの/変えるもの(例つき)、要確認、台帳の重複、月の抜けをメッセージで表示。
   「今のフォルダ構成を維持してファイル名だけ整える」か「年月フォルダ(例:`2026-09`)に再構成する」かを選び、了承した場合だけ実行(キャンセルすれば何も変わりません)
3. **実行**:読めたものは新しい名前で書き出し、読めなかったものは「要確認」フォルダへコピー。元ファイルは変更・削除しません。同名があれば `_2` `_3` を付けて上書きを避けます

- 書き出し先は「01 保存先を設定する」のフォルダ(Chrome/Edge)。**デモ版では書き出さず**、振り分け結果のプレビューと台帳記録のみ
- 学習済みの取引先に一致した場合は、書類種類・勘定科目を自動反映

### 電帳ダッシュボード(06)

「📊 電帳ダッシュボードを作成」で、台帳の内容を埋め込んだ**1枚のHTMLファイル**(`電帳ダッシュボード.html`)を作ります。
正式版では保存先フォルダの先頭に作成・更新します(デモ版ではプレビューのみ)。

- 取引先・日付・金額・ファイル名などで**検索**(スペース区切りでAND)、月・勘定科目で絞り込み、合計金額の表示
- 月ごとの件数を並べ、**抜けている月をオレンジで表示**
- ファイル名をクリックすると該当ファイルを開けます(ダッシュボードを置いたフォルダからの相対リンク)
- **画像・PDFをドラッグ&ドロップ、またはカメラで撮影して追記**:読み取り→ファイル名を作成→一覧に追記。読めなかった項目は「✎修正」で入力
- スマホではカメラ撮影ボタンから、撮った写真をそのまま取り込めます(PCではファイル選択になります)
- デモ版では追記はそのページ内の表示のみ(保存されません)。ページ下部に正式版のご案内を表示します
- 読み取りエンジン(Tesseract.js / pdf.js)はCDNから読み込むため、追記機能の利用にはネット接続が必要です

### 通知・処理レポート(06内)

処理内容を画面右下の通知と、履歴として残る「処理レポート」でお知らせします。

- 読めなかった項目の指摘(例:「取引年月日が読み取れませんでした」「取引先が『領収書』と読まれました」)
- 月の抜けの指摘(例:「2026年7月のファイルが見当たりません」)。一括整理後と、台帳の「📅 月の抜けをチェック」ボタンで実行
- 重複スキップ・書き出し失敗・インボイス番号の読み取り漏れの可能性など

## 電子帳簿保存法の検索要件について

国税庁の解説によれば、電子取引データの検索要件は以下の3点です。

1. 取引年月日・取引金額・取引先で検索できること
2. 日付または金額の範囲を指定して検索できること
3. 2つ以上の検索項目を組み合わせて検索できること

ただし、税務職員からのダウンロードの求めに応じられる場合は上記2・3は不要になり、
**基準期間の売上高が5,000万円以下の事業者は、すべての検索要件が不要**になります。
多くの個人事業主はこの緩和の対象です。

検索要件を満たす方法は、専用システムの導入以外に、**事務処理規程を整備した上で、
ファイル名に取引年月日・取引先・金額を含める**という運用でも認められています。
本ツールはこの「ファイル名で満たす」方式を前提に設計しています。

出典:[国税庁「電子帳簿保存法が改正されました」(2021年12月)](https://www.nta.go.jp/law/joho-zeikaishaku/sonota/jirei/pdf/0021005-038.pdf)

## 制度改正について

2026年9月末でインボイス制度の2割特例が終了し、個人事業主向けに3割特例が新設される
予定です。免税事業者からの仕入税額控除も段階的に縮小されるため、日々の証憑管理・
記帳の重要性は今後さらに高まります。本ツールは制度改正に合わせて継続的に
アップデートしていく予定です。


## 読み取り精度の改善(2026-10-08)
- カード明細(dカード/au PAY/TS CUBIC/楽天/三井住友ほか)を「明細書」として判定し、取引先をカード会社名にする
- 取引日がない明細・請求書は、支払日・請求年月・ファイル名の年月から日付を補完(補完した旨をプラン画面と処理レポートに表示)
- 金額は「ご請求金額」などのラベル付きを優先して抽出
- 全角/半角カナ・OCRの文字間スペースを正規化、項目名(「ご」「ご利用」等)を取引先として誤読しないよう除外
- 画像は拡大・グレースケール・コントラスト補正してからOCR、PDFは日本語CMapを読み込み


## 一括整理の設計変更(2026-10-08):「確認してから登録」方式
- 一括整理では、**確認なしで登録されるファイルはありません**。読み取り結果は必ず確認画面を通ります。
- **初めての書類**:1件ずつ確認画面を表示(プレビュー・日付/金額/取引先の候補チップ・書類種類・支払い方法・勘定科目)。「この内容で登録」で、取引先・種類・日付と金額の読み取り位置を「書類ルール」として記憶します。
- **2回目以降の同じ書式**:登録済みルールを適用し、結果を一覧で確認(行ごとに「修正」、チェックを外すと1件ずつ確認)。
- 同じバッチ内でも、1件目を登録した時点で、残りの同書式の書類は「適用して確認」に切り替わります。
- スキップした書類は「要確認」フォルダへ。確認が済むまでファイルにも台帳にも書き込みません。
- 書類ルールは「09」セクションで一覧・削除できます(判別キー:インボイス番号/取引先名/ファイル名パターン)。
- 単体の読み込みでも、同じルールを適用・学習します。


## 日付の規則と対象者(2026-10-08 決定)
- **対象者**:電子ファイル(メール添付の請求書・Web明細・スマホ撮影のレシート等)を受け取っている人すべて。個人事業主(青色・白色)・法人・副業の別、仕訳の有無、会計ソフトの有無を問わない。電子取引データの保存義務は青色限定ではない(青色限定なのは優良な電子帳簿の特典等)。
- **ファイル名の日付**:書類に記載された日付(購入日・請求日・利用月末など)。ただし**カード会社が発行する「カード利用明細」だけは引落日**(未払金の決済を表す書類のため)。
- **支払予定日**:カード払いの引落(予定)日は、ファイル名には入れず台帳・CSVの「支払予定日」列に別記録。現金主義・発生主義どちらの記帳でも、会計ソフトへ取り込む際に使い分けできる。
- 書類種類は「明細書(事業者の明細)」と「カード利用明細(カード会社の明細)」に分離。


## 重複登録の防止(2026-10-08)
- 確認画面・まとめ確認・単体読み込みのすべてで、台帳(と今回の処理済み分)と照合し、同じ書類らしきものを検出して警告。
- 判定:①ファイル内容(SHA-256)が同一 ②同じファイル名+同じ金額 ③日付・取引先・金額が同じ ④取引先・金額が同じで日付が20日以内(「可能性」扱い)。
- 重複らしき書類は、確認画面で「重複なので登録しない」(ファイルにも台帳にも何もしない)か「別の書類として登録する」を選ぶ。まとめ確認では重複らしき行はチェックを外した状態で表示し、外したまま進めると登録しない。
- 台帳にはファイルの内容ハッシュを保存(以前の記録にはないため、その場合はファイル名・金額・日付で照合)。

### 重複判定の見直し(2026-10-08)
- 毎月同額の請求があるため、「金額が同じ」だけでは重複とみなさない(必ず日付も見る)。
- ほぼ確実な重複:ファイル内容が同一 / 日付・取引先・金額がすべて同じ。→ まとめ確認では外したままだと登録しない。
- 要確認(似た記録):日付・取引先は同じで金額だけ違う(金額の訂正かも)/ 同じファイル名・金額で日付だけ違う / 取引先・金額が同じで日付が20日以内。→ 1件ずつ確認画面で判断(同じ書類の訂正なら「重複なので登録しない」+台帳の編集、別の書類なら「別の書類として登録する」)。

## カード利用明細の日付 = 登録カードの引落日

- 書類種類が「カード利用明細」のとき、取引年月日は「03 支払いカード」に登録したカードの支払日ルールで算出した**引落日**を最優先で使います(土日祝は翌営業日へ後ろずれ)。
- au PAYカードのプリセットは「15日締め・翌月10日払い」。例:2026年10月分の明細 → 2026-10-13(10日が土曜のため翌営業日)、11月分 → 2026-11-10。
- 明細に印字された引落日は第2候補として残ります。カードが未登録の場合は印字の引落日を使い、確認画面にその旨を表示します。
- 単体処理では、カードを自動選択し、締め日/引落日の欄に反映します。

## カード利用明細は「日付」と「支払い方法」を別扱い

- 取引年月日 = 登録カードの引落日(支払日)。
- 支払い方法 = 「カード支払に準拠」(個別のカードや現金を選ばせません)。確認画面でも自動でこの値になり、書類種類を切り替えると連動します。
- 台帳の「支払予定日」には引落日がそのまま入ります。

- カード利用明細の取引先 = カード名(登録カードがあればその名前。例:au PAYカード)。ファイル名も `日付_カード名_金額円_カード利用明細` になります。
- 事業者の請求書・明細書(BIGLOBEなど)の取引先は、これまで通り会社名です。カード利用明細だけ、取引先がカード名になります。
- カード発行会社の正式名(例:○○フィナンシャルサービス株式会社)が必要な場合は、確認画面の「カード発行会社の正式名」欄に入れると、台帳とCSV(会社名(正式)列)に記録されます。ファイル名には入りません。

## カード明細の取引先・税務調査対応

- カード利用明細の取引先 = `カード名(発行会社の略称)`。例:`au PAYカード(auフィナンシャルサービス)`。どちらの名前でも検索できます。正式名(例:auフィナンシャルサービス株式会社)は台帳・CSVの「会社名(正式)」に自動で入ります(主要カードの対応表は `CARD_COMPANIES`。実際の明細の表記と合っているか確認してください)。
- 台帳画面に追加:
  - 🧾 税務調査用の一覧(期間指定CSV):取引年月日・取引先・金額・書類種類・支払い方法・ファイル名・保存フォルダなど。ダウンロードの求めに応じる際の一覧として使えます。
  - 📝 訂正・削除履歴CSV:台帳の編集履歴+削除ログ。
  - 📄 事務処理規程のひな形:電子取引データの訂正削除防止規程の記載例(国税庁のサンプルのURL付き。必ず自社に合わせて修正してください)。
- 注意:「取引先」を略称で記録してよいかを明記した国税庁の資料は、確認できていません。公開前に税理士か国税庁で確認してください。

## 訴求の軸:税務調査に備える「検索システム(HTML)」と「一覧CSV」

- 電帳ダッシュボード(HTML)に、日付範囲・金額範囲・取引先の組合せ検索と「この結果を一覧CSVで保存」を追加。国税庁の特設サイト・一問一答・ダウンロードの求め・規程サンプルへのリンクを掲載。
- トップページ冒頭にも「税務調査で『見せて』と言われても慌てない」を掲載。
- 販売文面では「要件を満たす」と言い切らず、「国税庁の資料を確認のうえ」「検索できる状態にする」の表現を推奨(取引先の略称の扱いは未確認)。

## 支払いカードのプリセット拡充(約40パターン)

- 「03 支払いカード」はボタンで開閉(初期は閉じています)。「+ カードを新規登録(カード名で探す)」で、カード名検索つきの一覧から選ぶと締め日・支払日が入ります。
- 各社公式ページの案内(2026-10-08確認)をもとにした標準設定です。契約や券種で異なる場合があります(au PAY=管理番号の先頭で2通り、TS CUBIC=5日/20日締め、ライフ=27日/3日払い、エポス=27日/4日払い、三井住友=10日/26日払い 等は別項目に分けました)。
- 公式で確認できなかったもの(UC・アプラス・出光・アメックス・ヤマダ/ヨドバシ等)は、カード名だけ登録して日程は手入力にしています。デビットカードは即時引落のため対象外です。
- 「freee連携対応」の表示は、freee公式のカード一覧で確認できたものだけです(マネーフォワード・弥生は公式ページから一覧を取得できず、未確認のため表示していません)。
- カード利用明細の確認画面に、明細の印字引落日と登録カードの計算結果が違う場合の警告を追加しました。

- カードの登録は、これまで通り「+ カードを新規登録」から選ぶ方式です(自動登録はしません)。
- カード名の照合を改善(「dカード」のように短い名前も一致)。

## 税務調査で見られても問題ない表現・画面に

- ダッシュボード(生成HTML):タイトルを「電子取引データ 検索・一覧」に変更。「備え」等の表現を削除し、法令適合を保証しない旨の注記を追加。「閲覧モード」(証憑の追加・修正を隠す)を追加。デモ用の案内・価格表示は、デモ版でのみ表示(正式版の生成物には出ません)。
- ツール本体のページ:「これだけ押さえればOK」「ファイル名だけで満たせます」等の断定表現を削除し、国税庁の資料を案内する表現に変更。根拠のない制度ニュース(2割特例/3割特例)を削除。

## 制度ニュースと設定の「最新化」

- ツール上部の「制度アップデート」に「🔄 最新化」ボタンを追加。公開した `updates.json`(GitHubの a2e-works/dencho_DIY 直下)を取得して、ニュースとカードの標準設定(締め日・支払日の追加・修正)を反映します。起動時にオンラインなら、12時間に1回まで自動で確認します。
- 取得できないとき(オフライン・未公開)は、本体に入っている情報(2026-10-08時点)を表示します。
- 送信するのは更新ファイルの取得リクエストだけで、証憑データ・台帳は送りません。リンクは https のものだけ表示し、本文はテキストとして表示します。
- 更新の手順:`updates.json` を編集してGitHubにプッシュするだけで、全ユーザーに反映されます(アプリ本体の差し替えは不要)。`cards` には `{group,name,label,closingDay,paymentDay,monthOffset,note,freee}` を追加できます(同じ label は上書き)。
