# 電帳DIY(デモ版)

レシート・請求書・カード明細・払込用紙を「撮る・貼るだけ」で、日付・取引先・金額を自動で読み取り、
帳簿に残せる形式にファイル名を整えるツールです。

このリポジトリは**体験版(v1.0)**です。証憑データの解析処理はすべてブラウザ内で完結し、
外部サーバーに送信されることはありません(Googleドライブ連携を使う場合を除く)。

## デモの公開状況

## デモ版(v1.0)でできること — 手順

現時点でこのファイル一式(`index.html` + `lib/`)をそのまま開けば、以下がすべて実際に動きます。
体験版固有の制限(後述)はそのままですが、それ以外の主要機能はすでに使える状態です。

### 手順1. 保存先を設定する(任意)

1. 「01 保存先を設定する」を開く
2. 「フォルダを設定」を押し、任意のローカルフォルダを選択する
3. ※Chrome/Edgeで、`https://`または`http://localhost`経由で開いた場合のみ有効です。`file://`で直接開いた場合はこの機能は使えません

### 手順2. ファイルの命名ルールを決める

1. 「02 命名ルールを設定する」を開く
2. 並び順(取引年月日→取引先→金額 など)を3パターンから選ぶ
3. 「書類の種類をファイル名に含める」のチェックを必要に応じて切り替える

### 手順3. 支払いカードを登録する(カード払いがある場合)

1. 「03 支払いカードを管理する」を開く
2. 「+ カードを新規登録」から、カードの呼び方(例:楽天カード)だけを入力する(**カード番号・暗証番号・セキュリティコードは一切入力不要・保存されません**)
3. 登録したカードの「締め日」「支払日」を入力する
4. これで、このカードを使った証憑を読み込むたびに、引落予定日が自動計算されるようになる(非営業日・祝日は自動で翌営業日にずれます)

### 手順4. 証憑を読み込む

1. 「04 証憑を読み込む」を開く
2. 「カメラで撮影」「ファイルを選択」またはドラッグ&ドロップで証憑を読み込む(画像・PDF対応)
3. 自動抽出された取引年月日・取引先・金額・書類種類を確認し、必要なら修正する
4. カード払いの場合は「支払い方法」でカードを選ぶ(引落予定日が自動計算される)
5. 「これはカード明細など、複数の取引をまとめた証憑です」相当の判定は、書類種類で「明細書」を選ぶと自動的に切り替わる
6. 内容が良ければ「この内容で確定・台帳に記録する」を押す

### 手順5. 台帳を確認・出力する

1. 「05 台帳(Excel管理)」を開く
2. 処理した証憑が一覧に自動追加されていることを確認する
3. 「CSVでダウンロード」を押すと、Excelでそのまま開ける形式で書き出せる(**この機能は体験版でも無制限に利用可能**)

### 手順6. クラウド/ローカルとの同期を確認する(任意)

1. 「06 クラウド/ローカルとの同期を確認する」を開く
2. **ローカルフォルダとの比較**:手順1でフォルダを設定していれば、「ローカルフォルダと比較する」を押すだけで、台帳とフォルダの中身の差分(未保存・削除済みの可能性があるファイル)が分かる
3. **Googleドライブとの比較**(セットアップが必要、下記「Googleドライブ連携のセットアップ手順」参照)

### 手順7. 取引先の学習を確認・編集する

1. 「07 学習した取引先の表記」を開く
2. 一度読み込んだ取引先は、表記・書類種類・支払い方法が自動で記憶されていることを確認できる
3. 内容はその場で直接編集・削除できる

### Googleドライブ連携のセットアップ手順

「06」からGoogleドライブとの比較を使うには、**ご自身のGoogle CloudプロジェクトでOAuth Client IDを発行する必要があります**(開発元では発行できません)。

1. [Google Cloud Console](https://console.cloud.google.com/)で新規プロジェクトを作成する
2. 「APIとサービス」→「有効なAPIとサービス」から**Google Drive API**を有効化する
3. 「OAuth同意画面」を設定する(User Type:外部。**テストユーザーとしてご自身のGoogleアカウントを追加**すればGoogleの本審査は不要)
4. 「認証情報」→「OAuth クライアント ID」を作成する(アプリケーションの種類:ウェブアプリケーション。承認済みのJavaScript生成元にアプリの公開URLを追加)
5. 発行されたClient IDを「06」の入力欄に貼り付けて保存する

**制約:**

- 使用スコープは`drive.file`(機密性の低いスコープ、厳格な審査は不要)
- ただし`drive.file`は**このアプリ経由で開いた・作成したファイルにしかアクセスできません**。別の方法で既にドライブに置いてあるファイルは一覧に出てきません
- OAuth同意画面が「テスト」ステータスのままだと、**テストユーザーとして登録した本人(最大100人まで)しかログインできません**。第三者への配布にはGoogleの本番審査が別途必要です

### 体験版固有の制限(そのままにしています)

- 1セッションにつき10件まで(`TESTING_MODE`フラグにより現在は一時的に無制限表示)
- ファイル本体の保存(ローカルフォルダへの書き込み・ダウンロード)は無効化(台帳への記録・CSV出力は制限なし)
- 払込用紙(電気・ガス・税金等)は検出のみで、内容の自動判定は非対応

## フォルダ構成

```
.
├── index.html         メイン画面
└── lib/
    ├── pdf.min.js       PDF解析ライブラリ(自前配信)
    └── pdf.worker.min.js
```

`index.html` は `lib/` フォルダ内のファイルを相対パスで参照しています。
公開・配布の際は、この2つのファイルを含む `lib/` フォルダごと一緒に配置してください。

## 技術構成

- PDF解析:[pdf.js](https://mozilla.github.io/pdf.js/)(自前配信)
- 画像OCR:[Tesseract.js](https://tesseract.projectnaptha.com/)(CDN経由、インターネット接続が必要)
- Googleドライブ連携:Google Identity Services + Drive API v3(利用時のみ外部通信が発生します)
- 上記以外はサーバー・バックエンドなし、データはブラウザ内(localStorage/IndexedDB)で処理・保存

## 注意事項

- 本デモはサンプルです。読み取り精度は体験版仕様のため、正式版より低く設定しています。

## 電子帳簿保存法の検索要件について

国税庁の解説によれば、電子取引データの検索要件は以下の3点です。

1. 取引年月日・取引金額・取引先で検索できること
2. 日付または金額の範囲を指定して検索できること
3. 2つ以上の検索項目を組み合わせて検索できること

ただし、税務職員からのダウンロードの求めに応じられる場合は上記2・3は不要になり、
**基準期間の売上高が5,000万円以下の事業者は、すべての検索要件が不要**になります。
多くの個人事業主はこの緩和の対象です。

検索要件を満たす方法は、専用システムの導入以外に、**事務処理規程を整備した上で、
ファイル名に取引年月日・取引先・金額を含める**という運用でも認められています。
本ツールはこの「ファイル名で満たす」方式を前提に設計しています。

出典:[国税庁「電子帳簿保存法が改正されました」(2021年12月)](https://www.nta.go.jp/law/joho-zeikaishaku/sonota/jirei/pdf/0021005-038.pdf)

## 制度改正について

2026年9月末でインボイス制度の2割特例が終了し、個人事業主向けに3割特例が新設される
予定です。免税事業者からの仕入税額控除も段階的に縮小されるため、日々の証憑管理・
記帳の重要性は今後さらに高まります。本ツールは制度改正に合わせて継続的に
アップデートしていく予定です。
